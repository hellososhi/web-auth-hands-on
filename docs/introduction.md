## この教材で作るもの

最初のアプリでは、全員が同じメモ一覧を見られます。メモを作った人と、編集・削除する人を区別する仕組みもありません。

このアプリに、次の機能を順に追加します。

1. ユーザー名とパスワードで登録する。
2. 登録した情報でログインする。
3. 次のリクエストでも、ログインした利用者を判断する。
4. 自分のメモだけを閲覧・編集・削除する。
5. ログアウトや有効期限によって、ログイン状態を終了する。
6. 許可していない操作が拒否されることを確かめる。

Better Authを使ったときに呼び出していた「登録」「ログイン」「ログアウト」の内側を、小さな処理に分けて作っていきます。

## 学習のゴール

完成したコードを使って、次の問いに答えられることを目指します。

- サーバーは、どの情報を根拠に利用者を判断しているか。
- パスワードをそのまま保存しないのはなぜか。
- Cookieには何を入れ、DBには何を保存しているか。
- ログインした利用者が他人のデータを操作できないのは、どの処理によるものか。
- コピーされたセッショントークンを、どう使えなくするか。
- 変更後も仕様が守られていることを、どう確認するか。

## 最初に分けておく3つの言葉

**認証**は、提示されたパスワードなどを確認し、どのアカウントとして扱うかを判断することです。この教材で確認するのはアカウントの認証情報です。

**セッション管理**は、複数のリクエストを同じログイン状態に結び付け、その開始・継続・終了を管理することです。

**認可**は、その利用者に、そのデータや操作へのアクセスを許すか判断することです。

例えば、Aさんの正しいパスワードでログインできても、Bさんの非公開メモの編集は拒否する必要があります。

参考：[Next.jsの認証ガイド][ref-next-auth]

## 各章の進め方

各章では、次の順番で作業します。

1. **予想**：どのような情報や条件が必要か考える。
2. **仕様と理由**：満たす条件と、その目的を確認する。
3. **設計・実装**：DBや関数を設計してコードを書く。
4. **確認**：手動操作と自動テストで結果を調べる。
5. **説明**：その実装が必要な理由を、自分の言葉にする。

自動テストは第2章で導入します。最初は小さな関数から始め、後の章でDBやAPIを含めて確認します。
